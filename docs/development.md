# 개발 작업 안내

## 현재 구현 상태

이 저장소는 기획 문서와 작업 지침을 갖춘 Git 저장소다. 아직 앱, 패키지 설정, DB, 채점 엔진, 결제 연동, CI/CD, 배포 주소는 없다. 특정 언어·프레임워크·결제 제공자를 임의로 선택하지 않았다.

## 로컬에서 시작

```bash
git clone https://github.com/gogogshark/MBTI-relationship.git
cd MBTI-relationship
git status
```

편집할 폴더는 위에서 복제한 저장소다. 기존 로컬 복사본이 있으면 별도 clone 대신 해당 작업 폴더의 변경과 원격 상태를 먼저 확인한다.

## 작업 순서

1. 루트 `AGENTS.md`, 현재 상태, 결정 기록을 읽는다.
2. 요청 범위와 현재 확정된 요구를 확인한다.
3. 최신 원격 상태를 확인하고 작업 브랜치를 만든다.
4. 해당 변경과 문서를 갱신하고 필요한 검증을 수행한다.
5. 변경을 커밋·푸시하고, 검토가 필요한 작업은 PR로 공유한다.

예시 브랜치 이름: `docs/service-flow`, `feat/auth`, `feat/payments`. 실제 기능 구현·마일스톤이 승인되었다는 의미는 아니다.

## ChatGPT Work / Codex

- 현재 세션의 Git 작업 폴더와 ChatGPT 프로젝트의 영구 환경 설정은 별개다.
- 이 저장소를 사용하는 새 작업에서는 저장소 URL 또는 로컬 작업 폴더를 지정하고 최신 문서를 읽도록 한다.
- 클라우드 개발 환경이 필요하면 계정 UI에서 해당 저장소를 선택한 환경을 생성·선택해야 한다.
- 공식 안내: [Codex Cloud](https://learn.chatgpt.com/docs/cloud), [프로젝트와 대화](https://learn.chatgpt.com/docs/projects).
- 이번 GitHub 문서 반영만으로 UI 환경 생성·게시, 다른 대화의 자동 연결, 대화 원문 자동 커밋이 완료되지는 않는다.

## 구현 전 정할 내용

상품 단계·접근권한·차액 정책, 인증 방식과 저장 기간, 검사·채점 범위, 기술 스택, 데이터 구조, 결제 제공자, 운영·배포 환경, 검증 기준을 정해야 한다. 기획 문서가 해당 선택을 대신 확정하지 않는다.

## 공개 저장소 범위

기획·연구 요약과 코드만 보관한다. 실제 참가자 자료·비밀키·계정정보를 저장하지 않는다. `.gitignore`는 흔한 경로를 제외하지만, 커밋할 파일의 내용 확인을 대체하지 않는다.
